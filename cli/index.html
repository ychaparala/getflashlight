    flashlight

    Flashlight — FOCUS-based multi-cloud spend visualization

    Usage:

    $ flashlight [OPTIONS] COMMAND [ARGS]...

    Options:

    • --install-completion: Install completion for the current shell.
    • --show-completion: Show completion for the current shell, to copy it or customize the installation.
    • --help: Show this message and exit.

    Commands:

    • init: Scaffold the lake home (FLASHLIGHT_HOME,...
    • sample: Download the FinOps FOCUS sample dataset...
    • ingest: Pull billing from all enabled connectors...
    • transform: Rebuild GOLD Parquet from the current...
    • cleanup: Remove ALL lake data — every BRONZE/GOLD...
    • aws: AWS Data Exports setup
    • mcp: MCP server for agents
    • dashboard: NiceGUI dashboard for humans

    flashlight init

    Scaffold the lake home (FLASHLIGHT_HOME, else the platform user-data dir) with a starter connections.yml. Run once. (Use sample to seed demo data.)

    Usage:

    $ flashlight init [OPTIONS]

    Options:

    • --force: Overwrite existing config/sample
    • --help: Show this message and exit.

    flashlight sample

    Download the FinOps FOCUS sample dataset and seed it for the dashboard.

    With --clean, removes everything the sample seeded (BRONZE partitions, cached CSVs, run-log entries) and rebuilds GOLD — other connectors are left untouched.

    Usage:

    $ flashlight sample [OPTIONS]

    Options:

    • --rows <int>: Sample size: 1000 or 10000 [default: 1000]
    • --url <str>: Override the FOCUS sample CSV URL
    • --force: Re-download even if cached
    • --clean: Remove all seeded sample data instead of seeding
    • --help: Show this message and exit.

    flashlight ingest

    Pull billing from all enabled connectors into BRONZE, then refresh views.

    Every connector runs even if an earlier one fails — a broken source doesn't block the others. GOLD is rebuilt from whatever succeeded; the command exits non-zero afterward if anything failed.

    Usage:

    $ flashlight ingest [OPTIONS]

    Options:

    • --start <str>: ISO start date (default: 35d lookback)
    • --end <str>: ISO end date (default: today)
    • --connections <str>: Path to connections.yml
    • --connector <str>: Only run this connector (its configured name, or type if unnamed)
    • --no-transform: Skip SILVER/GOLD refresh
    • --run-id <str>: Identify this sync in the run log with a caller-supplied id instead of generating one (the dashboard passes its own so it can name a saved-log file before the subprocess starts — see dashboard/ingest_runner.py).
    • --full-refresh: Wipe each connector's ENTIRE bronze history before pulling --start/--end (not just that window's partitions) — use after a config change (e.g. a narrower include_services) so stale out-of-window data doesn't linger. Composes with --start/--end: they still control what gets pulled back in. Without --start/--end, that's just the default 35-day lookback, so anything older than that is gone unless the source can still provide it — pass a wide --start explicitly to rebuild full history. Does not affect efficiency/driver-health metrics (keyed by provider, shared across connectors, and already window-scoped).
    • --help: Show this message and exit.

    $ flashlight transform [OPTIONS]

    Options:

    • --help: Show this message and exit.

    flashlight cleanup

    Remove ALL lake data — every BRONZE/GOLD Parquet and the run log.

    Wipes everything the writers produce under FLASHLIGHT_HOME, leaving only config/. Destructive and irreversible; re-seed with sample or ingest. To remove only the seeded sample, use sample --clean instead. To remove only one connector's BRONZE data (e.g. before re-pointing it at a different account), pass --connector.

    Usage:

    $ flashlight cleanup [OPTIONS]

    Options:

    • --connector <str>: Only remove this connector's data (e.g. aws_focus, databricks, redshift) — every other connector's BRONZE/GOLD is left untouched.
    • --dry-run: Show what would be removed without removing it
    • -y, --yes: Skip the confirmation prompt
    • --help: Show this message and exit.

    Options:

    Commands:

    • create-export: Create the AWS FOCUS 1.2 Data Export this...
    • bucket-policy: Merge-apply the S3 bucket policy AWS Data...

    • update-export: Update the AWS FOCUS Data Export in place...
    • delete-export: Delete the AWS FOCUS Data Export.

    flashlight aws create-export

    Create the AWS FOCUS 1.2 Data Export this platform consumes.

    Walks you through each input (bucket, prefix, region) with the resolved value as the default — press Enter to keep it, or type a new one — then confirms before provisioning. --yes takes the resolved values as-is.

    Usage:

    $ flashlight aws create-export [OPTIONS]

    Options:

    • --bucket <str>: Destination S3 bucket
    • --prefix <str>: Destination S3 prefix
    • --s3-region <str>: Bucket region
    • --name <str>: Export name [default: flashlight-focus]
    • --description <str>: [default: FOCUS 1.2 export consumed by Flashlight]
    • --time-granularity <str>: HOURLY | DAILY | MONTHLY [default: DAILY]
    • --overwrite <str>: OVERWRITE_REPORT | CREATE_NEW_REPORT [default: OVERWRITE_REPORT]
    • --query-statement <str>: Override the FOCUS column projection
    • --connections <str>: connections.yml for bucket/prefix defaults
    • --dry-run: Print the request without creating the export
    • -y, --yes: Use resolved values without prompting; skip confirmation
    • --help: Show this message and exit.

    flashlight aws bucket-policy

    Merge-apply the S3 bucket policy AWS Data Exports needs (--dry-run to just print it).

    Usage:

    $ flashlight aws bucket-policy [OPTIONS]

    Options:

    • --bucket <str>: S3 bucket
    • --region <str>: Bucket region (default: config)
    • --connections <str>: connections.yml for defaults
    • --dry-run: Print the policy without applying it to the bucket
    • --help: Show this message and exit.

    flashlight aws update-export

    Update the AWS FOCUS Data Export in place (e.g. fix its S3 prefix after editing config).

    Walks you through each input (bucket, prefix, region) with the current value as the default — press Enter to keep it, or type a new one. Then prints a before→after plan of every field UpdateExport changes, flags the bucket-policy step if the bucket moves, and confirms before applying. --yes takes the resolved values as-is.

    Usage:

    $ flashlight aws update-export [OPTIONS]

    Options:

    • --bucket <str>: Destination S3 bucket
    • --prefix <str>: Destination S3 prefix
    • --s3-region <str>: Bucket region
    • --name <str>: Name of the existing export to update [default: flashlight-focus]
    • --description <str>: [default: FOCUS 1.2 export consumed by Flashlight]
    • --time-granularity <str>: HOURLY | DAILY | MONTHLY [default: DAILY]
    • --overwrite <str>: OVERWRITE_REPORT | CREATE_NEW_REPORT [default: OVERWRITE_REPORT]
    • --query-statement <str>: Override the FOCUS column projection
    • --connections <str>: connections.yml for bucket/prefix defaults
    • --dry-run: Print the plan without updating the export
    • -y, --yes: Use resolved values without prompting; skip confirmation
    • --help: Show this message and exit.

    flashlight aws delete-export

    Delete the AWS FOCUS Data Export. Parquet already in S3 is left untouched.

    Usage:

    $ flashlight aws delete-export [OPTIONS]

    Options:

    • --name <str>: Name of the export to delete [default: flashlight-focus]
    • --connections <str>: connections.yml for AWS credentials
    • --dry-run: Show what would be deleted without deleting it
    • -y, --yes: Skip the confirmation prompt
    • --help: Show this message and exit.
